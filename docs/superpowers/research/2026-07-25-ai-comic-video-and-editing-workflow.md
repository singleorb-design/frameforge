# 当代 AI 漫剧视频生成与剪辑流程调研

> 调研快照：2026-07-25
> 目标：为影格工坊设计“只生成生产指令、不直接生成视频”的工业级工作流。
> 说明：即梦的模型名称、会员权限、参考数量和界面入口会持续变化。产品实现应使用可更新的“平台能力档案”，不要把当前界面参数写死在分镜数据中。

## 一、结论摘要

画布不应该把“分镜 Markdown”直接改写成一段即梦提示词。生产级交付物应是逐镜头的“外部生成任务单”，任务单同时包含：

1. 镜头的叙事目的和可验收的开始、结束状态。
2. 即梦生成模式：首帧、首尾帧、智能多帧或全能参考。
3. 该模式需要上传的控制资产及其顺序、角色和引用名称。
4. 比例、分辨率、时长、声音策略、候选数量等设置。
5. 可直接粘贴的最终提示词。
6. 即梦中的逐步操作说明。
7. 结果验收标准、失败诊断和重试策略。
8. 回填画布后的版本、采用片段和剪辑说明。

“首帧审核”不能作为所有镜头的统一门禁。正确的统一门禁是“镜头生成方案审核”：

- 首帧模式：审核首帧。
- 首尾帧模式：同时审核首帧、尾帧及二者之间的可达性。
- 智能多帧模式：审核关键帧顺序、每帧目的和节奏。
- 全能参考模式：审核参考资产是否完整、是否冲突，以及每个引用在提示词中的职责。

尾帧与首帧同等重要。尾帧定义动作落点、情绪落点、构图落点和下一镜头的连续性入口。并非所有镜头都需要上传尾帧，但所有镜头都必须描述“结束状态”。

## 二、官方能力事实

### 2.1 即梦和 Dreamina

- 即梦官网明确提供文生视频和图生视频，并宣传“从首帧到尾帧，精准掌控”，说明首帧图片和尾帧图片是正式的可控生成方式。[1]
- Dreamina 官方帧转视频页面把 `First and last frame`、`Multiframe` 和 `Omni reference` 列为不同的视频控制路径，并要求用户补充动作、转场或场景风格提示。[2]
- 该页面给出的操作流程包括：进入 AI Video、选择首尾帧或多帧模式、上传图片序列、填写提示词、设置 FPS/时长/分辨率/格式、生成，再进行插帧、放大或配乐处理。[2]
- Dreamina 的首尾帧说明强调：首尾帧用于控制开始和结束状态，模型负责生成中间运动；开始图和结束图之间的角色、物体、场景布局越连贯，过渡越稳定。[3]
- Dreamina 当前的 Seedance 2.0 Mini 说明中，全能参考可混合图片、视频和音频，并通过 `@` 标签在提示词中指定引用职责；该页面当前列出的上限是 12 个参考，其中包含最多 6 张图片、3 个视频和 3 个音频。[4]
- 同一说明中，Multiframe 当前最多支持 10 张参考帧，可控制帧顺序和每一帧的停留区间；这类数量和时长属于平台动态能力，不能作为永久不变的业务规则。[4]
- 即梦当前页面数据将 Seedance 2.0 描述为音频、视频、文本、图片均可参考的全模态模型，但不同模型、会员档位和真人脸限制不同。[1]

### 2.2 Seedance API 与网页产品不是同一能力档案

- 火山方舟 Seedance 2.0 API 把首帧和尾帧定义为两个不同的图片角色：`first_frame` 与 `last_frame`。[5]
- 当前项目内已有的 Agent Plan API 适配上限为 9 张参考图、3 个参考视频和 3 个参考音频，这与 Dreamina/即梦网页中特定模型页面的“12 个参考”并不完全相同。
- 因此，“即梦 Web”“Dreamina Web”“火山方舟 API”必须作为不同的平台能力档案管理。即使底层模型同属 Seedance，也不能共用一套固定参数。

### 2.3 多参考和短剧工业流程

- 火山引擎对 Seedance 2.0 多图参考的说明将其价值归纳为风格统一、人物/场景/道具元素复用和按图片顺序完成场景过渡。[6]
- 火山剧创的官方介绍采用“剧本解析 -> 素材设定 -> 分镜解析 -> 视频生成 -> 剪辑导出”的生产链，并在生成前检查人物、场景和道具是否配置完整。[7]
- 火山剧创还强调全局风格锁定、角色/变装/场景/关键道具资产库、上下文状态跟踪和确认后的分镜序列导出到剪映。[7]
- 可灵的官方材料同样把多图角色参考、起止帧、视频延长和多模态参考作为提高一致性和可控性的核心能力，说明“参考资产 + 起止状态 + 镜头任务”已经是当代视频模型的共同生产范式。[8][9]

### 2.4 剪映后期能力

- 剪映官网当前列出文本朗读、智能调色、音频降噪、响度统一、蒙版、关键帧、调色、多时间线和音频剪辑等能力。[10]
- 这意味着画布虽然不执行剪辑，仍可以输出可操作的剪映时间线执行单，包括画面、声音、字幕、调色、关键帧和导出要求。

## 三、四种视频生成模式的生产定义

### 3.1 首帧模式

适用：

- 单一主体的小动作。
- 情绪近景、反应镜头、道具特写。
- 结束姿态不需要精确锁定。
- 镜头的主要价值是让一张已确认构图“动起来”。

必备资产：

- 一张已审核首帧。
- 明确的结束状态文字，即使不上传尾帧也不能省略。

提示词重点：

- 主体做什么。
- 动作幅度和速度。
- 摄像机怎么动。
- 背景中允许发生什么。
- 结束时停在哪里。

主要风险：

- 结束状态不可控。
- 人脸、手、道具在长动作中漂移。
- 同时描述多个动作和运镜时，模型自行取舍。

### 3.2 首尾帧模式

适用：

- 动作有明确起点和落点。
- 需要变身前后、开门前后、转身前后、起身/坐下等状态转换。
- 需要精确控制镜头最终构图。
- 需要将当前镜头尾部状态交给下一连续镜头。
- 需要可循环、匹配剪辑或视觉转场。

必备资产：

- 一张已审核首帧。
- 一张已审核尾帧。
- 首尾帧相容性检查。

相容性检查：

- 同一角色身份、服装、发型和关键道具。
- 场景几何、主光方向和时间状态不矛盾。
- 画面比例一致。
- 起点到终点在给定时长内可以自然完成。
- 不要在一个短片段中同时要求大幅换景、换装、换机位和复杂肢体动作。

主要风险：

- 首尾差异过大导致融化、瞬移或中间帧畸变。
- 尾帧虽然好看，但不是动作可达状态。
- 为了锁尾帧牺牲了中间运动自然度。

### 3.3 智能多帧模式

适用：

- 一个镜头或小段落存在 3 个以上必须保留的视觉节点。
- 产品展示、仪式过程、连续姿态变化、受控转场。
- 需要控制事件顺序和节奏，不只是开始与结束。

必备资产：

- 有序关键帧列表。
- 每一帧的剧情职责。
- 帧间节奏或目标时间点。

生产约束：

- 每一帧都必须推动动作、信息或情绪，不能把相似图堆进去。
- 若关键帧对应多个机位、多个场景和多个叙事镜头，应拆成多个镜头，不应让多帧模式替代剪辑。
- 每个生成片段仍应只有一个主要动作方向和一个主要运镜意图。

主要风险：

- 关键帧过多导致模型只做画面串联，动作缺少因果。
- 多场景硬塞进一个片段，生成结果像转场演示而不是戏剧镜头。

### 3.4 全能参考模式

适用：

- 角色身份、场景、道具、动作或运镜需要分别参考不同资产。
- 需要引用角色三视图、表情、场景定妆图、道具图、动作视频或音频节奏。
- 首尾构图不是最主要约束，重点是多种参考的组合执行。

必备资产：

- 带职责的参考清单，而不是无差别上传全部资产。
- 与平台上传顺序一致的引用名称。
- 在提示词中通过 `@` 指定每项参考的用途。

推荐参考职责：

- `@角色A`：只参考脸、发型、服装和体型。
- `@场景1`：只参考空间结构、材质、光线和色调。
- `@道具1`：锁定形状、材质、颜色和持有方式。
- `@动作参考`：只参考运动节奏和身体路径，不复制人物身份。
- `@运镜参考`：只参考摄像机轨迹和节奏。
- `@音频参考`：参考节奏、口型或情绪起伏。

主要风险：

- 参考资产相互冲突。
- 上传过多但未说明职责，模型不知道保留什么。
- 把角色三视图直接当最终构图，导致画面僵硬。
- 用全能参考替代首尾帧，结果身份一致但结束构图不可控。

## 四、为什么必须设计尾帧

尾帧有四层职责：

1. **镜头内部动作落点**：人物最终站位、手中道具、视线、表情和摄像机位置。
2. **戏剧落点**：揭示、反应、打脸、悬念等情绪停点。
3. **剪辑出口**：下一镜头从什么状态接入，是否可以动作匹配、视线匹配或声音先行。
4. **连续生成锚点**：同一连续动作需要拆成多个生成片段时，前段尾帧可作为后段首帧候选。

需要区分两种连续性：

- 连续长镜拆段：前一片段尾帧应尽可能成为下一片段首帧，或使用平台的视频延长能力。
- 正常剪切换机位：不要求两帧像素相同，但人物姿态、道具手、屏幕方向、视线、服装、时间和光线状态必须连续。

所以数据结构中每个镜头都要有 `endState`，只有部分镜头需要进一步拥有 `endFrameAssetId`。

## 五、生产级 AI 漫剧流程

### 阶段 1：剧本结构化

- 把 Markdown 剧本拆成场次、剧情节拍、对白、旁白、动作、情绪转折和钩子。
- 建立稳定 ID，后续所有角色、场景、道具和镜头都引用 ID，不引用易变化的文本名称。

### 阶段 2：全局资产定稿

- 人物卡、变装状态、角色三视图、表情和景别参考。
- 场景卡、场景全景、主要机位、时间/天气/灯光变体。
- 道具卡、关键道具正反面、尺寸和持有关系。
- 全局风格、色彩、画幅、安全区和目标平台。

### 阶段 3：结构化分镜

每个镜头至少定义：

- 剧情目的、情绪、信息增量。
- 景别、机位、构图、视线和屏幕方向。
- 开始状态、动作过程、结束状态。
- 角色、变装、场景和道具绑定。
- 对白/旁白/SFX、预估时长和剪辑关系。

### 阶段 4：声音与粗剪节奏

- 在最终视频生成前确认对白和旁白的预计时长。
- 用关键帧、临时配音和静态分镜形成 animatic/节奏表。
- 先发现镜头冗余、节奏拖沓和对白装不下的问题，再生产高成本视频。
- 镜头时长应来自表演与声音，而不是统一写成 5 秒。

### 阶段 5：镜头生成方案

- 自动推荐首帧、首尾帧、智能多帧或全能参考。
- 解释推荐原因，并允许人工改选。
- 生成该模式所需的控制帧或参考资产清单。
- 完成“镜头方案审核”后才能编译最终即梦任务单。

### 阶段 6：即梦外部生产

- 画布生成逐步操作单和最终提示词。
- 用户在即梦上传指定资产、设置参数并生成候选。
- 对高风险镜头生成多个候选，但每次只改变一个变量：动作、运镜、参考或时长。
- 用户把候选或最终采用视频上传回画布，记录来源任务和版本。

### 阶段 7：镜头验收

检查：

- 角色身份、服装、场景、道具和画面风格。
- 起始状态、结束状态、动作完整度和运镜。
- 手脸畸变、穿模、闪烁、物体增减和文字水印。
- 与前后镜头的屏幕方向、视线、动作、光线和声音连续性。
- 最终采用区间，不要求整段生成视频全部可用。

### 阶段 8：剪映精剪

画布输出逐镜时间线执行单：

- 素材文件名、采用版本、入点、出点和目标时长。
- 画面顺序、变速、定格、关键帧缩放和转场。
- 对白、旁白、环境声、动作音效和 BGM 情绪段。
- 字幕文本、说话人、入点、出点和强调样式。
- 镜头级调色修正与全片统一 LUT/色彩要求。
- 片头钩子、结尾悬念、封面候选和导出规格。

推荐剪辑顺序：

1. 对白/旁白主轨和节奏。
2. 画面粗剪与反应镜头。
3. 动作音效和环境声。
4. BGM 与闪避。
5. 字幕和重点字。
6. 连续性修复、变速和转场。
7. 镜头匹配调色和全片调色。
8. 响度、画质和导出验收。

## 六、对影格工坊的产品含义

### 保留

- 剧本 Markdown 节点。
- 人物卡组、人物卡和角色视觉资产包。
- 通用图片、视频上传和 Markdown 阅读能力。
- 显式连接和 `@` 引用的可理解性。

### 缺失

- 场景卡组、场景卡和场景视觉资产。
- 道具卡组、道具卡和道具视觉资产。
- 结构化分镜表与可寻址镜头。
- 镜头开始/结束状态和跨镜连续性。
- 逐镜生成模式选择。
- 首帧、尾帧、关键帧序列和多模态参考的不同语义。
- 即梦 Web 平台能力档案。
- 提示词编译版本和所用资产快照。
- 外部操作任务单、候选回填和验收。
- 剪映时间线执行单。

### 推荐模块

使用一个深的 `Shotboard` 模块管理镜头生产，而不是继续把字段堆入通用节点 metadata。

画布只保存：

- 分镜组节点 ID。
- 镜头子节点 ID。
- 视觉位置、折叠状态和连接。
- 对应领域记录 ID。

`Shotboard` 模块管理：

- 场次和镜头顺序。
- 角色/场景/道具绑定。
- 开始状态、结束状态和连续性。
- 生成模式及控制资产。
- 即梦任务单、提示词版本和平台能力快照。
- 候选、采用版本、验收和剪辑交接。

Markdown 分镜继续作为可读报告和导出格式，但不再作为生产数据的唯一真相来源。
