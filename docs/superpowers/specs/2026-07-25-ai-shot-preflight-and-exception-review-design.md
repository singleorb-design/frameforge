# AI 镜头预整理与异常审核设计

## 背景

当前结构化分镜已经包含剧情目的、情绪、镜头语言、开始状态、动作、结束状态、声音、资产绑定等生产字段，但镜头工作台仍以专业表单为主。用户需要理解并维护大量导演和摄影术语，也必须手动选择人物、场景、道具及其版本。

生产流程应调整为：

1. 结构化分镜生成后，整集自动执行 AI 预整理。
2. 系统优先依据剧本结构、对白、连线资产和已有版本化资产完成确定性匹配。
3. AI 只补充语义信息和不能通过规则确定的状态。
4. 高置信度且无阻塞的镜头自动确认。
5. 用户默认只处理异常，不逐项填写专业字段。

## 目标

- 正常镜头不要求用户操作。
- 用户只看到能理解的镜头摘要、资产匹配结果和异常问题。
- 人物、场景、道具优先使用生成配置直接连接的资产，当前画布资产作为兜底。
- AI 不自动创建缺失资产；缺失时提供 Prompt、生成结构化资产卡草案和一键生图入口。
- 人工修改永久优先，AI 不覆盖人工锁定字段。
- 所有 AI 改动可追溯、可撤销、可重新整理。

## 非目标

- 不接入视频生成。
- 不自动登录或操作即梦。
- 不允许 AI 改写剧本台词、剧情节拍、镜头 ID、镜头顺序或来源关系。
- 不允许 AI 直接发布缺失资产。
- 不自动替换用户已选中的参考图版本。
- 不为群演、普通桌椅和背景装饰创建正式资产。

## 用户流程

### 结构化分镜生成

```text
单集剧本 + 导演要求 + 连线资产
                ↓
          结构化分镜生成
                ↓
      整集 AI 预整理自动启动
                ↓
    高置信度镜头自动确认并保存
                ↓
  缺失、冲突、低置信度进入异常队列
```

生成配置节点在预整理期间继续显示运行状态。成功提示应同时汇报：

- 镜头总数。
- 自动确认数量。
- 需处理数量。
- 整理失败数量。

分镜已经成功、预整理失败时，不回滚分镜；分镜表保留并显示“预整理失败，可重试”。

### 镜头工作台

默认镜头定义页不再展示完整专业表单，而是展示：

- 一句话镜头标题。
- 可读镜头摘要。
- 景别、角度、运镜、时长的紧凑摘要。
- 开始状态、动作过程、结束状态三段式流程。
- AI 已匹配的人物、场景、道具和版本。
- 每项匹配依据与置信度。
- 当前异常。

原专业字段收纳进“高级编辑”，默认折叠。用户修改任一字段后，该字段加入人工锁定列表。

右侧栏改为：

1. 当前镜头状态。
2. 异常与建议。
3. 缺失资产处理。
4. 生成模式摘要。
5. 历史和 AI 整理记录。

### 整集异常审核

分镜表工作台增加“异常审核”视图：

```text
第 1 集 · 19 镜头
已自动确认 15 | 需处理 3 | 整理失败 1
```

默认只列出异常镜头，可切换查看全部镜头。

异常分级：

- `blocking`：缺少主角、主场景、关键道具、引用失效、连续性错误。
- `review`：人物冲突、低置信度匹配、服装或状态推断、版本过期。
- `optional`：空镜无人、普通背景物、轻微镜头语言建议。

允许批量执行：

- 重新整理全部异常镜头。
- 重新检查整集。
- 忽略全部可选异常。
- 生成全部缺失资产卡草案。
- 采用全部高置信度资产卡草案。

阻塞异常不可忽略。

## 混合整理引擎

### 输入上下文

每个镜头只使用当前生产所需上下文：

- 当前 `ScriptBreakdown`。
- 当前镜头和相邻前后镜头。
- 镜头引用的剧情节拍、对白和旁白。
- 生成配置直接连接的资产 ID。
- 当前画布版本化人物、场景、道具目录。
- 用户人工锁定字段。
- 当前跨镜连续性检查结果。

不把完整多集剧本发送给整理模型。

### 确定性匹配

规则引擎先处理高确定性关系：

- 对白 `speaker` 与人物卡名称精确匹配。
- 剧情节拍和镜头文本中的标准人物名称匹配人物卡。
- `StoryScene.locationAssetId` 和场次位置匹配场景卡。
- 镜头文本、剧情节拍和道具状态中的标准名称匹配道具卡。
- 已有合法绑定保留。
- 直接连接资产优先于画布兜底资产。
- 同名多版本默认使用资产当前版本，但已有绑定保持原版本。

低置信度候选不自动绑定。

### AI 语义补全

AI 只返回镜头补丁，不返回完整 Shotboard：

```ts
type ShotPreflightPatch = {
  shotId: string;
  fields: Partial<ShotEditableFields>;
  fieldSources: Record<string, FieldSource>;
  assetMatches: AssetMatchSuggestion[];
  issues: ShotPreflightIssue[];
  confidence: "high" | "medium" | "low";
};
```

AI 可补全：

- 可读镜头标题和摘要。
- 剧情目的、情绪节拍、信息增量。
- 开始状态、动作过程、结束状态。
- 人物镜头职责和人物状态。
- 场景时间、光线和空间状态。
- 道具状态变化。
- 景别、角度、构图、运镜、时长和音效建议。
- 连续性说明。

AI 响应必须通过 Zod 和领域校验。无效镜头 ID、无效资产 ID、无效版本或试图修改禁止字段时，该镜头整理失败，不写入半成品。

### 分批策略

一次模型请求最多处理 8 个镜头，并携带前后镜头的只读连续性摘要。整集请求按场次分批，最多并发 2 个请求。

这样可以：

- 控制上下文长度。
- 避免一个坏 JSON 破坏整集。
- 让局部失败可重试。
- 保持跨镜状态有最小必要上下文。

### 字段合并规则

字段优先级：

```text
人工锁定值
> 当前合法资产绑定
> 确定性规则结果
> 高置信度 AI 结果
> 原始结构化分镜值
```

AI 只填空字段或替换未锁定的低质量初始值。用户修改字段后永久锁定，除非用户：

- 点击单字段“允许 AI 重写”。
- 点击镜头“解除全部人工锁定”。
- 恢复到没有该锁定的历史版本。

### 自动确认条件

镜头同时满足以下条件才自动确认：

1. 必填字段完整。
2. 场景绑定合法。
3. 剧情中出现的主要人物均高置信度绑定。
4. 关键道具均已绑定。
5. 所有资产版本存在。
6. 没有 `blocking` 或 `review` 异常。
7. 没有跨镜连续性错误。
8. AI 整理结果为高置信度。
9. 用户没有标记“始终人工确认”。

自动确认生成正常镜头 revision，并保留整理批次记录。

## 数据模型

### 镜头 AI 元数据

```ts
type FieldSourceKind =
  | "script"
  | "dialogue"
  | "connected-asset"
  | "canvas-asset"
  | "rule"
  | "ai"
  | "user";

type ShotFieldSource = {
  fieldPath: string;
  source: FieldSourceKind;
  sourceId?: string;
  confidence: "high" | "medium" | "low";
  reason: string;
};

type ShotPreflightIssue = {
  id: string;
  kind:
    | "missing-character"
    | "missing-scene"
    | "missing-prop"
    | "ambiguous-character"
    | "ambiguous-asset"
    | "state-conflict"
    | "stale-version"
    | "insufficient-context"
    | "invalid-ai-patch";
  severity: "blocking" | "review" | "optional";
  message: string;
  shotIds: string[];
  assetKind?: "character" | "scene" | "prop";
  suggestedName?: string;
  candidateAssetIds?: string[];
  prompt?: AssetDraftPrompt;
  status: "open" | "resolved" | "ignored";
};

type ShotPreflightState = {
  status: "pending" | "running" | "ready" | "needs-review" | "failed" | "user-locked";
  confidence: "high" | "medium" | "low";
  batchId?: string;
  fieldSources: ShotFieldSource[];
  lockedFieldPaths: string[];
  issues: ShotPreflightIssue[];
  lastRunAt?: string;
  error?: string;
};
```

`Shot` 增加：

```ts
preflight: ShotPreflightState;
```

### 整理批次

`ShotboardRecord` 增加：

```ts
preflightBatches: ShotPreflightBatch[];
```

批次快照包含：

- 剧本结构版本。
- 连线资产 ID。
- 画布资产当前版本。
- 处理镜头 ID。
- 每镜头结果和错误。
- 自动确认数量。
- 创建时间。

历史最多保留 20 个批次。

### 缺失资产草案

草案不进入正式版本化资产目录：

```ts
type AssetDraft = {
  id: string;
  kind: "character" | "scene" | "prop";
  name: string;
  sourceShotIds: string[];
  sourceBeatIds: string[];
  data: CharacterCardSnapshot | SceneCard | PropCard;
  imagePrompt: string;
  negativePrompt: string;
  recommendedRatio: string;
  status: "draft" | "adopted" | "discarded";
  createdAt: string;
};
```

同一批次内相同 `kind + normalizedName` 只生成一份草案。

## 缺失资产补全

### 异常卡

缺失资产异常展示：

- 建议资产名称。
- 使用镜头。
- 剧情作用。
- 需要的状态变化。
- AI 生成的正向 Prompt。
- 负向 Prompt。
- 推荐比例。

操作：

- `AI 生成资产卡`
- `复制 Prompt`
- `绑定已有资产`
- `忽略`，仅 `optional` 可用

### AI 生成资产卡

点击后使用所有相关镜头、节拍和对白生成一份结构化草案。

草案必须先展示摘要：

- 人物：身份、外观、一致性锁定、服装和关键道具。
- 场景：空间布局、材质、色调、光线和连续性锁定。
- 道具：造型、材质、尺寸、状态和操作规则。

用户点击“采用资产卡”后：

1. 创建正式版本化资产。
2. 投影为画布资产卡和对应卡组；已有同类卡组时加入现有卡组。
3. 自动绑定所有引用该缺失资产的镜头。
4. 重新运行相关镜头的规则匹配和连续性检查。
5. 满足条件的镜头自动确认。

### 生成参考图

正式资产卡提供：

- `使用模型生成`
- `复制 Prompt 到外部平台`

人物沿用现有角色资产流程：

1. 标准人物设定图。
2. 三视图。
3. 表情九宫格。
4. 景别参考。

场景参考图要求无人物、固定空间结构。道具参考图根据状态输出单图或状态对照图。

外部制作说明包含正负 Prompt、比例、分辨率、参考上传顺序、操作步骤和回传入口。

### 3D 资产 Prompt 编译

缺失资产异常中的保底 Prompt 只用于帮助用户理解缺失内容，不能直接作为最终外部生图 Prompt。资产卡草案成功后，系统必须根据完整资产字段编译生产级 Prompt。

默认视觉方向：

```text
高质量动画 3D 国风玄幻漫剧
```

人物标准设定图 Prompt 必须包含：

- 角色名、身份、剧情功能和叙事气质。
- 年龄感、性别、身形、脸型五官、发型、发色、瞳色。
- 服装的款式、材质、层次、主辅色、宗门或家族标记。
- 默认表情与镜头中的核心情绪。
- 关键道具与佩戴位置。
- 一致性锁定词。
- 全身单人、站立、三分之二侧前方、干净中性背景、角色完整可见、无遮挡。
- 3D 建模质量、PBR 材质、电影级柔光、清晰轮廓、适合后续三视图和分镜引用。

人物负向 Prompt 必须包含：

```text
2D 平涂、纸片人、真人照片、写实真人脸、Q版、低模、玩具塑料感、比例畸形、多人、截断身体、手指错误、文字、水印、logo、模糊、过曝、现代无关元素
```

场景标准参考图必须包含空间布局、材料、色调、光线、时间、天气、连续性锁定词、无人物、3D 动画场景建模、16:9 横向构图。

道具标准参考图必须包含造型、材质、颜色、尺寸、状态、操作规则、连续性锁定词、居中无手持展示、3D PBR 产品级建模、干净背景。

资产卡还应提供三个用途不同的 Prompt：

1. `标准设定图`：第一次建立角色/场景/道具视觉母版。
2. `三视图 / 多角度图`：人物使用正面、侧面、背面；道具使用多个角度；场景不使用三视图。
3. `镜头参考图`：基于已锁定资产和镜头状态，用于后续镜头控制帧。

复制到外部平台时，UI 必须同时复制：

- 正向 Prompt。
- 负向 Prompt。
- 推荐比例。
- 推荐用途。
- 人物三视图和表情/景别参考的上传顺序说明。

## 状态与生命周期

### 初次生成

```text
draft
→ preflight.running
→ ready / needs-review / failed
→ shot-approved（仅自动确认合格镜头）
```

### 剧本或资产变化

- 剧本版本变化：受影响镜头标记 `pending`，不覆盖人工字段。
- 资产新版本：显示“有新版本可同步”，不自动改变已有绑定。
- 资产被删除：相关镜头产生阻塞异常。
- 用户修改镜头：修改字段加入 `lockedFieldPaths`，镜头回到草稿。
- 已发布即梦任务存在时：AI 整理不修改任务；镜头内容变化后任务按现有规则变为 stale。

## 错误处理

- 规则匹配失败只产生异常，不阻止其他镜头。
- 单个 AI 批次失败不回滚已成功批次。
- AI 返回无效 JSON 时沿用现有 `jsonrepair + 一次受约束模型修复`。
- AI 补丁引用不存在的镜头或资产时拒绝该镜头补丁。
- 自动确认失败时保留“已准备”，记录具体阻塞项。
- 缺失资产草案生成失败时保留原异常和可复制 Prompt。
- 生图失败不删除正式资产卡，可重试或转外部制作。

## UI 细节

### 分镜表

顶部增加：

- AI 整理进度。
- 已自动确认、需处理、失败数量。
- `重新整理异常`
- `重新检查整集`
- `异常审核`

### 镜头工作台

默认展示紧凑摘要，不出现以下裸字段：

- `informationGain`
- `screenDirection`
- `editRelation`
- 原始分类枚举

这些字段使用中文标签收进高级编辑。

AI 绑定行显示：

```text
沈夜 · v1 · 主角 · 退婚前/隐忍
依据：对白 + 剧本精确命中
```

低置信度不显示为已绑定，而进入异常卡。

### 可解释性

每个 AI 值允许展开“为什么”：

- 来源。
- 置信度。
- 使用的节拍或资产。
- 是否可以由 AI 重写。

## API 与模块边界

新增模块：

- `shot-preflight-context.ts`：构建最小上下文。
- `shot-asset-matcher.ts`：确定性资产匹配。
- `shot-preflight-schema.ts`：模型输出 Schema。
- `shot-preflight-compiler.ts`：合并补丁、字段来源和人工锁定。
- `shot-preflight-runner.ts`：分批、并发和失败隔离。
- `asset-draft.ts`：缺失资产 Prompt、草案生成、采用。

页面层只负责：

- 发起模型请求。
- 显示进度。
- 应用纯函数返回的 Production 更新。

领域模块不直接读取 React 状态或调用网络。

## 验收标准

### 自动整理

- 一集结构化分镜生成后自动进入整理。
- 连线资产优先，画布资产兜底。
- 高置信度匹配自动保存。
- 正常镜头自动确认。
- 失败镜头不影响其他镜头。

### 人工锁定

- 修改任一高级字段后，该字段不被后续整理覆盖。
- 解除单字段或整镜锁定后才允许 AI 重写。
- 历史版本恢复同时恢复锁定状态。

### 异常审核

- 默认只展示异常镜头。
- 异常使用中文业务描述，不要求用户理解内部字段名。
- 阻塞项不可忽略。
- 同一缺失资产只出现一个聚合异常。

### 缺失资产

- 不自动发布资产。
- Prompt 可复制。
- 一键生成只创建草案。
- 采用后创建正式版本化资产并自动绑定相关镜头。
- 参考图可选择模型生成或外部制作。

### 兼容与持久化

- 旧 Shot 缺少 `preflight` 时归一为 `pending`。
- 刷新、撤销/重做、导出/导入保留整理状态、字段来源、人工锁定、异常、批次和资产草案。
- 已发布任务不被整理过程直接覆盖。

## 实施顺序

1. 数据模型与纯函数规则匹配。
2. AI 上下文、Schema、分批 runner 和整集自动触发。
3. 自动确认、人工锁定与历史。
4. 镜头工作台摘要化与高级编辑。
5. 分镜表异常审核。
6. 缺失资产 Prompt、草案、采用和画布投影。
7. 参考图入口接入现有资产生成流程。
8. 持久化、导出导入和人工验收文档。
