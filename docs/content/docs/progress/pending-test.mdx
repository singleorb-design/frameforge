# 待测试

本次 AI 漫剧生产流程请优先按照[完整验收清单](/docs/progress/ai-comic-production-acceptance)执行并记录结果。下面保留各版本变更概要。

- Codex 插件短剧生产 skill：安装或刷新 FrameForge 插件后，新任务中输入“把这个短剧剧本放到 FrameForge 画布生产”“生成角色场景道具参考图 Prompt”“逐镜视频 Prompt”等请求，应触发 `drama-production`；该 skill 应优先使用 `canvas` / `open-canvas` 操作画布，并按剧本、资产、图片 Prompt、分镜、视频 Prompt、外部任务单等阶段创建或规划可编辑节点，不应把完整网文写作工具箱流程作为默认主线。
- 项目改名：GitHub README、浏览器标题、文档站首页、部署文档、商务/安全说明、Codex 插件展示名、插件安装 ID、MCP 工具名、导出标识、本地存储 key 和项目目录均应统一使用“影格工坊 / FrameForge / frameforge”。
- 整理角色设定章节选择：任意剧本点击“角色设定”都应先显示按 Markdown 同级标题拆分的章节列表，默认只勾选第一章，可逐章勾选、全选或清空，并实时显示已选章节数与字符数；无可拆分标题时应显示“全文”一项；点击生成后只能发送勾选章节，未选择时不可生成；模型 Prompt 应明确禁止续写并要求只返回严格 JSON；失败的角色组点击“重试”应重新打开章节选择并在原节点生成，不应重复创建角色组。
- 超长剧本性能：打开包含百万字级剧本的画布后，悬停节点、缩放和平移不应因剧本统计反复计算而明显卡顿；双击剧本应按章节显示并可通过目录、上一章和下一章切换；编辑时连续输入不应逐键刷新整张画布，停止输入约 800ms、切回阅读、关闭或按 `Esc` 后应保存最新内容；复制仍应得到完整 Markdown。
- 生成配置右侧连线：选中或悬停“生成配置”节点时右侧应显示输出连线点；从右侧拖出应能连接到用户上传的图片、视频或音频资产节点，连线方向保持“生成配置 -> 资产节点”，且左侧已有输入连线能力不受影响。
- 图片复制：图片节点悬浮工具栏应显示“复制图片”；点击后可将图片写入系统剪贴板，并能粘贴到支持图片剪贴板的浏览器输入框或桌面应用；浏览器不支持时应提示可改用下载。
- 剧本全屏退出：双击“剧本”节点进入全屏阅读器后，焦点在阅读正文、目录按钮或编辑输入框内时按 `Esc` 都应退出全屏阅读器。
- 《月光樱花门》全季文档：检查 `docs/generated/sakura-season-novel.md` 是否包含 12 集小说正文，`docs/generated/sakura-season-screenplay.md` 是否包含 12 集制作剧本、分镜和即梦生成段落示例；角色引用应使用 G05 组图位置命名，视频段落应符合 10 秒生成段落规则。
- 主题驱动 3D 动物短剧 skill：输入“樱花节”“中秋”等主题后，确认方向和剧本，再验证最终交付默认面向即梦全能参考模式；角色素材应来自 `/Users/bytedance/Documents/ai漫剧/动物/人物角色` 重建后的 5 张组图，角色关键动作句应写“G01 右一垂耳兔花瓣收集者”“G01 左二赤狐春日信使”“G03 右一浣熊磁带 DJ”这类组图位置加具体动物名加角色短名，不应只写角色短名；分镜应拆细，但即梦 Prompt 应默认按 8-10 秒生成段落组织，一个生成段落可覆盖 1-3 个连续分镜，并标明覆盖分镜、场景参考图、人物参考图、必要道具参考图和连续性简介，正文必须以“生成视频：X 秒，”开头，不应输出首帧、尾帧或首尾帧上传方案；蒙太奇段落应先拆成多个短分镜，再按连续性合并为生成段落；牌子、信件、书页等可读文字不应交给即梦或图片模型生成，应保留空白承载物并输出视频软件文字层清单；角色面向树枝、牌子、舞台等目标物时，应同时写清镜头站位、身体朝向、可见角度和禁止回头/看镜头等约束，参考图朝向冲突时应明确不继承参考图朝向；场景图和视频 Prompt 应包含固定画质关键词：超清细节、主体锐利、眼睛高光清晰、毛发细节丰富、衣服纹理清楚、边缘锐利、减少景深虚化、高清写实动画、4K、sharp focus、high detail、crisp edges；主体始终清晰对焦，避免运动模糊，背景轻微虚化但主体边缘锐利。
- 本地磁盘持久化：在仓库根目录执行 `make` 后，新建画布并上传或生成图片、视频、音频，确认画布 JSON、素材、生成记录、API 配置和原始媒体均写入 `data/`；刷新浏览器、重启 `make`、删除浏览器站点数据或换浏览器访问后应恢复同一批磁盘项目；媒体文件字节不得经过 ZIP、gzip、Base64 持久化、图片重编码或音视频转码；本地存储服务不可用时页面应阻塞且不得回退 IndexedDB；两个标签页同时编辑旧 revision 时不得静默覆盖；API Key 应明文写入被 Git 忽略的 `data/settings.json`；旧 IndexedDB 数据应保留但不读取、不迁移、不删除。
- AI 镜头预整理与异常审核：结构化分镜成功后应自动按场次分批整理整集镜头，每批最多 8 镜、最多并发 2 个请求；规则应优先精确匹配对白说话人、场次和道具，生成配置直接连线资产优先于画布兜底资产；高置信度且无阻塞/复核异常的镜头应自动进入“已确认”，单批失败不能回滚分镜或其他成功批次；分镜表生产看板应显示“已自动确认 / 需处理 / 整理失败”数量，默认只展示异常镜头，并支持“重新整理异常”“重新检查整集”和进入具体镜头处理。
- 动作与道具识别：镜头中的“沈夜手持玉佩”必须识别沈夜为人物、玉佩为道具；不得生成“缺少人物：手持玉佩”。存在正式道具“旧玉佩”时，“玉佩”应自动匹配该道具；已保存的同类错误人物异常在刷新后应自动清理。
- 人物词过滤：身份、人物身份、角色设定、人物设定、角色、人物、镜头、场景、动作、状态、剧情、画面、信息和设定等语义词不得作为人物名或“缺少人物”资产草案；旧画布刷新后同类异常必须自动清理。
- 口语状态词过滤：都废了、配不上、认命、笑话等状态、评价或口语短句不得作为人物名或“缺少人物”资产草案；旧画布刷新后同类异常必须自动清理。
- 人物来源收紧：人物识别只能来自人物目录、角色卡或对白说话人；不得从普通剧情句子中按“少主/小姐/师兄”等称谓猜测新人物名。没有角色词典时，“沈家少主都废了”不应生成缺少人物；角色词典已有“沈夜”且镜头文本明确出现“沈夜”时，才可生成“缺少人物：沈夜”。
- AI 人物异常白名单：AI 返回的缺少人物若不在人物目录、角色卡、对白说话人或候选资产中，应在解析阶段丢弃；退婚也正、独自等半截句子不得显示为缺少人物。
- 已有角色重新匹配：苏婉儿等角色设定已存在时，旧分镜中同名“缺少人物”异常必须在画布恢复或上传该角色参考图后自动关闭；恢复画布或上传角色图均应完成同名角色匹配，再将已有图片接入已确认镜头，不能继续显示已中断的 AI 补齐失败。
- 同名角色消歧：项目中存在多条同名角色记录时，优先采用已经上传视觉参考的记录；直接打开受影响镜头也必须立即执行角色同步与异常重连，无需再次刷新或重新上传图片。
- 同名角色手动选择：多个同名角色仍无法自动判断时，异常卡应显示候选角色按钮；点击候选后自动绑定、关闭“匹配到多个资产”异常并继续推进到下一步。
- 镜头自动推进：分镜整理、画布恢复、上传角色参考图或打开镜头后，只要不存在真实阻塞，系统应自动采用推荐生成方式、带入现有视觉参考并进入“准备画面”；用户不需要确认镜头或确认方案。
- 准备画面自动采用：首帧、尾帧和关键帧上传后应直接可用，历史待确认上传图在打开镜头时也应自动采用；满足必需画面后直接显示“生成外部任务”，不得要求再点“通过”。
- 准备画面图片预览：首帧、尾帧、关键帧以及自动带入的角色/场景/道具参考图在准备画面页必须显示缩略图预览，不能只展示文件名；本地文件缺失时应显示不可预览提示。
- 异常优先中断：普通警告只作提示，不阻塞镜头推进；只有必填字段、场景绑定和阻塞级素材异常显示在“必须处理”，解决后系统自动继续。
- 创作者镜头主线：镜头工作台默认按“检查分镜 → 准备画面 → 外部生成 → 回传结果”组织；没有真实阻塞时自动进入准备画面，必需画面就绪后显示“下一步：生成外部任务”，外部任务准备好后显示“下一步：上传外部生成结果”。内部资产快照、镜头修订、控制图迭代和平台档案仍保留，但主流程不显示 `v1/v2`、版本化资产、历史版本或能力档案。
- 参考图回流镜头：上传角色、场景或道具的外部参考图后，所有绑定同一素材且没有真实阻塞的镜头应自动接入该图作为角色、场景或道具参考；工作台显示“已接入 N 张视觉参考”，整集看板与镜头节点显示视觉参考数量，不要求再次上传或人工确认。
- 异常优先镜头工作台：镜头定义页默认只展示 AI 可读摘要、紧凑镜头语言、开始/动作/结束三段流程、匹配素材与中文异常，原专业字段收进“高级编辑”；人物、场景、道具只显示名称和状态，手动改素材、生成方式和恢复历史收进“更多调整”；用户修改任一字段后应锁定该字段，后续 AI 整理不得覆盖，允许单字段或整镜点击“允许 AI 重写”；正常镜头不需要逐镜点击确认。
- 缺失资产草案：缺失主要人物、主场景或关键道具时，不得直接创建正式资产；异常卡应展示建议名称、影响镜头、可复制正负 Prompt 和“AI 生成资产卡”；草案生成后可丢弃、采用或“采用并生成参考图”；采用后只创建一份版本化正式资产，投影到已有或新建的对应卡组，自动绑定所有相关镜头、解决同名异常并重新校验；参考图失败不能回滚正式资产卡和镜头绑定。
- 资产卡草案数组兼容：模型把唯一资产草案输出为单元素数组，或多项数组中仅有一项名称与建议资产名一致时，应自动取用该对象并继续展示草案；多个对象都不匹配或无法唯一确定时，必须提示“资产卡草案返回了多个对象，无法确定应采用哪一项”，不得随机采用。
- 资产卡草案结构兼容：模型以平铺资产字段、`asset` / `assetCard` / `payload` 内嵌字段，或遗漏 `recommendedRatio` 返回草案时，应归一化后继续校验；比例仅可按人物 `3:2`、场景 `16:9`、道具 `1:1` 推导。人物外观、服装、一致性锁定，场景布局、光线、来源说明，道具状态等创作字段缺失时，必须显示对应字段错误而非静默补造。
- 资产卡生成反馈：点击“AI 生成资产卡”后，所有引用同一缺失资产的异常卡应立即显示“AI 正在生成资产卡”并禁用重复点击；成功后显示资产卡草案与采用操作；失败后卡片内必须显示模型错误原因和“重新生成资产卡”，刷新页面后状态和错误原因仍应保留。
- 资产卡生成结束边界：生成中卡片应显示已等待秒数并提供“停止生成”；停止后应立即恢复为可重新生成状态；请求超过 90 秒时必须显示“资产卡草案生成超时”错误并保留外部 Prompt；刷新页面后此前的生成中任务必须显示“页面刷新导致资产卡生成中断”，不能永久停在加载状态。
- 3D 资产 Prompt 编译：缺失资产尚未生成草案时，复制的临时 Prompt 必须包含相关镜头/对白上下文、高质量动画 3D 国风玄幻漫剧、PBR 材质、完整主体构图和 3D 负向词；草案生成后复制 Prompt 应包含完整资产字段、正向 Prompt、负向 Prompt、推荐比例、用途和外部制作流程，人物标准设定图需包含身份、外貌、服装、关键道具、一致性锁定和全身三分之二侧前方构图；采用并生成参考图必须使用同一生产级 3D Prompt。
- 外部生成图回填：人物、场景和道具正式资产卡应显示“上传外部生成图”入口；上传图片后必须创建持久化参考记录和连接的图片节点，不得替换资产卡文本或覆盖旧参考图；人物回填的标准参考图应作为后续三视图生成的图生图母版；绑定该素材且无真实阻塞的镜头应自动接入对应人物、场景或道具参考。
- 自动生成方式与旧剧本人物识别：镜头没有阻塞异常且没有未保存修改时，应自动采用 AI 推荐生成方式并进入“准备画面”；已有分镜的来源剧本在首次“重新整理异常 / 重新检查整集”时，应从“主要人物”章节补齐角色名单，开场无对白但明确出现角色名的镜头若无人物资产，必须显示“缺少人物”阻塞异常和素材补齐入口，不能仅提示“空镜可忽略”。
- AI 检查整集可见反馈：生产看板的“AI 检查整集”应明确说明其只重新匹配资产、补镜头摘要/状态、归集异常，不改写台词、镜头顺序和人工锁定字段；点击后按钮应进入“AI 正在检查镜头”加载态，显示逐场检查提示并禁用重复操作；完成后应更新统计并弹出自动确认、需处理和失败数量，若当前没有异常镜头应明确提示“当前没有需要整理的异常镜头”。
- AI 整理资产状态兼容：模型在 `assetStates` 或 `issues` 中附带 `continuityLocks` 等资产目录描述字段时，系统应仅保留镜头整理允许字段并继续执行严格的镜头 ID、资产 ID、版本和枚举校验；顶层结构错误、未知资产或未知镜头仍必须报错。
- 整集交付阶段 4：镜头工作台应可上传多个即梦 mp4/mov 候选，逐项验收、设置入点/出点、目标时长、变速/定格/裁切/补帧/转场/调色和剪辑备注，只有全部验收通过的候选才能采用并进入剪辑就绪；采用候选可固定为视频节点；镜头、控制资产或任务变化后旧采用候选应 stale；双击分镜表应打开整集生产看板，按场次展示镜头状态、模式、候选与阻塞，支持跨镜人物版本/状态、场景、道具、屏幕方向和首尾状态检查，warning 可确认、error 不可忽略；工作包允许不完整并生成 issues，最终剪辑包必须全部有采用视频、当前任务和连续性检查且没有 error；ZIP 应包含实际 control-frames/selected-clips、shotboard JSON/Markdown/CSV、即梦任务、jianying-edit-plan.csv、dialogue-voiceover.md、subtitles.srt、audio-cue-sheet.csv、issues.md 和 manifest.json；不得生成剪映私有草稿或调用视频生成接口。
- 即梦任务单阶段 3：系统自动选择生成方式后，准备画面页应按首帧、首尾帧、智能多帧或全能参考显示必需/可选项；支持复制控制帧 Prompt和上传替换图片，上传后直接采用；必需项齐全后状态应进入“可外部生成”；外部任务应校验模型、模式、比例、时长、分辨率和参考上限，输出上传顺序、`@` 引用、最终 Prompt、禁止项、操作步骤、验收与重试；替换画面应把旧任务标为 stale；控制图与外部任务可按需固定到画布，重复固定应聚焦已有节点，删除固定节点不能删除领域记录；整个页面不能出现视频生成或任务轮询入口；刷新及导出/导入后应保留内部快照和任务历史。
- 镜头工作台阶段 2：双击镜头应进入全屏工作台，`Esc` 退出；编辑开始状态、动作、结束状态、镜头语言、时长和声音 Cue 后点击保存，应只增加一个镜头 revision，撤销/重做应同时恢复 Production 数据和镜头卡标题/状态；人物、场景、道具应绑定明确内部快照；缺少必需字段、场景或引用无效素材时应暂停自动推进；没有真实阻塞时应自动选择生成方式并进入准备画面；再次编辑镜头后保存应自动重新计算生成方式；恢复历史内容应作为新 revision；刷新及导出/导入后应保留 revision、绑定、阻塞项和内部方案。
- 镜头人物版本化资产：已有画布刷新后，所有有效人物卡应自动登记到 Production 人物资产并回写 `productionRecordId` / `productionVersion`；双击任意镜头后，“版本化资产 > 人物绑定”下拉应列出画布全部人物卡，即使人物卡组未连接到结构化分镜配置；新批量生成的人物卡应立即进入下拉；编辑人物卡后再次打开镜头工作台应新增版本并默认展示最新版，旧镜头已绑定版本仍可保留；没有人物卡时下拉应显示“画布暂无可用人物资产”。
- 结构化分镜阶段 1：将非空 Markdown 剧本直接连接到生成配置，文本模式输出选择“结构化分镜”后应生成场景卡组、道具卡组和分镜表；分镜表展开后应显示按场次和镜号排序的镜头节点，折叠/展开动画、连线、一键整理和撤销应正常；双击分镜表应全屏阅读由 Shotboard 派生的 Markdown，不能编辑派生报告；模型返回非法 JSON、重复 ID、丢失剧情节拍或无效资产引用时不应创建任何半成品节点，配置节点应显示具体字段错误并保留原始输出；刷新、导出 v4 压缩包并重新导入后，生产数据、节点和连线应完整恢复。
- 结构化分镜模型兼容：连接包含多集内容的剧本并在配置中要求“把第一集生成短剧分镜”，实际请求应只携带公共设定和第一集正文；旧配置提示词即使已经包含一份完整剧本，也不应重复发送；模型遗漏场景/道具 `sourceNote`，或返回 `character-intro`、`character-exit`、`fantasy-reveal`、`plot-twist`、`cliffhanger`、`fade`、`dissolve` 等常见别名时应能正常生成；人物目录为空时模型自造人物 ID 不应阻塞生成，有正式人物目录时无效人物引用仍必须报错；重复 ID、悬空节拍/镜头、无效场景道具引用和时长偏差仍应阻止创建半成品。
- 结构化分镜连续性与时长归一：模型为新增场景或道具返回空 `continuityLocks` 时，应自动补充包含资产名称的整体一致性约束；模型镜头总时长与目标时长存在 60%-140% 范围内的偏差时，应保持各镜头相对节奏并精确缩放到目标总时长，例如 54.5 秒的镜头表应归一为 90 秒；缺少合法镜头时长或偏差超出范围时仍必须报错。
- 结构化分镜 JSON 自动修复：模型返回缺少引号、逗号、括号或被截断的 JSON 时，应先通过本地 `jsonrepair` 修复；模型返回 `"n目"`、`"n婚书撕毁"` 等损坏字段名且本地无法确定语义时，应自动调用当前文本模型修复一次，修复请求不得携带整份剧本或改写镜头内容、台词、ID、引用、顺序、画幅和时长；修复结果仍须通过完整 Schema 与引用校验；自动修复最多执行一次，仍失败时配置节点应保留最终错误和最后一次原始输出，不得创建半成品。
- 空白画布框选：指针位于空白画布时应显示十字光标，左键拖动应框选相交节点，Shift + 左拖应追加框选，空白按下时应关闭节点悬浮工具栏和人物卡编辑面板，空白单击应取消选择；按住 Space + 左拖、鼠标中键拖动和触控板双指滑动应继续平移画布；框选完成后点击“一键整理”应只整理当前框选节点。
- 一键整理画布：底部工具栏点击“一键整理”后，无选中节点时应整理全画布，有选中节点时只整理选中范围；节点应按连线从左到右分层，同层纵向排列；展开的图片批次、人物卡组和角色资产包若子节点重叠，应重新排成两列网格；折叠集合应保持折叠并整体移动，普通 Group 内部相对位置不变；整理后应自动缩放居中，撤销应恢复整理前的位置和视口。
- 角色视觉资产包：人物卡悬浮工具栏点击“角色资产”后应能选择“模型生成 / 外部制作”；模型生成时三视图必须先生成，表情九宫格和景别参考应使用三视图作为参考图继续生成；外部制作时应展示三类 Prompt 和操作流程，至少上传三视图，点击“导入画板”后创建同样的资产包结构；最终应创建“角色资产包”主节点和真实图片子节点，并自动连接“人物卡 -> 角色资产包 -> 图片”；双击资产包应折叠/展开，子图片和连线应按批量图片相同的飞入/飞回动画显示或隐藏。
- 批量生成人物卡：在有内容的剧本节点悬浮工具栏点击“人物卡”，应弹出批量配置；生成后应创建 1 个“人物卡组”主节点和多个人物卡子节点，并自动连接“剧本 -> 人物卡组 -> 人物卡”；双击人物卡组应能折叠/展开，展开时人物卡和连线都应显示，子卡应从主节点堆叠位置飞出；收起时人物卡应飞回主节点，动画结束后子卡和连线隐藏，并显示类似批量图片的堆叠效果；人物卡应展示角色定位、外观、一致性锁定词，并能作为文本资源连接下游节点；模型输出 JSON 解析失败时应在人物卡组保留错误状态而不是创建错误人物卡。
- Markdown 文档节点：新建“文档”节点后应显示空态；双击进入全屏阅读器，按 `Esc` 应退出全屏；粘贴包含标题、表格、引用、列表和分割线的 Markdown 后应正确渲染；配置节点切到文本模式时应能在“普通文本 / Markdown 文档”之间切换输出类型，选择 Markdown 文档后生成结果应落到文档节点；若模型输出包含 `<think>...</think>`，最终节点内容不应包含该思考块；Markdown 文档节点连接到下游配置节点后，下游应能读取完整 Markdown 文本。
- Markdown 剧本节点：新建“剧本”节点后应显示空态；双击节点进入全屏阅读器，按 `Esc` 应退出全屏；粘贴 Markdown 后应渲染标题、段落、列表、引用和分隔线；目录应按 `#` / `##` / `###` 标题生成并可跳转；编辑后切回阅读应立即更新；复制按钮应复制原始 Markdown；剧本节点连接到生成配置节点后，下游应能读取完整 Markdown 文本。
- 默认入口：访问 `/` 或点击左上角「影格工坊」应直接进入 `/canvas`，不再显示原首页；404 和错误页的返回按钮应回到「我的画布」。
- MiniMax 生图渠道：在配置弹窗点击「新增 MiniMax 生图」后，应自动创建 Base URL 为 `https://api.minimaxi.com/v1` 的 OpenAI 渠道，内置 `image-01` 生图模型且带 MiniMax `/v1/image_generation` 调用脚本；填写 API Key 后设为默认生图模型，画布生图应按所选比例返回图片。
- 配置节点文本生成：一个文本节点连接一个生成配置节点并切到「文本」模式时，点击生成应只创建 1 个文本结果；生图模式仍按画布默认生图张数输出多张图片。
- MiniMax 文本渠道：在配置弹窗点击「新增 MiniMax 文本」后，应自动创建 Base URL 为 `https://api.minimaxi.com/v1` 的 OpenAI 渠道，内置 `MiniMax-M2.1`、`MiniMax-M2.1-highspeed`、`MiniMax-M3` 文本模型且带 MiniMax Chat Completions 调用脚本；填写 API Key 后设为默认文本模型，画布文本生成应能返回文本。
- 全站 Agent 稳定性：连接本地 Agent、打开右侧助手、切换对话/历史/日志、刷新页面后不应再出现 `Maximum update depth exceeded`；若页面仍发生运行异常，应展示中文错误页，并可重新加载或返回首页。
- 全站 Agent Hermes 接入：安装并配置 Hermes 后启动 `npx -y @basketikun/canvas-agent`，网页右侧助手应通过 `hermes acp` 新建、恢复、删除会话并展示 Hermes 流式回复；若 `hermes acp` 不可用，应在日志或错误消息里显示启动失败原因。
- 画布手势：在触控板上双指左右或上下滑动应平移画布，不应触发缩放；双指捏合仍应以指针位置为中心放大或缩小画布，缩放速度应比上一版更跟手。
- 提示词来源：6 个内置来源应从 Image Prompts 统一仓库读取，更新后数量依次为 323、494、53、76、126、129；提示词仍按 6 个来源分组并可独立启用，来源内可继续按 `tags` 筛选。添加标准 JSON URL 后应能查看内容，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 我的提示词：在提示词中心切换到「我的提示词」，验证新增、编辑、删除和搜索；从提示词库保存后应出现在个人列表、画布左侧提示词面板和提示词选择弹窗中，刷新页面后数据仍保留在本地，Agent 搜索提示词时也应能查到。
- 画布提示词库：不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Hermes turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；关闭当前页面后应回退到最近聚焦且仍连接的页面，其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Hermes 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Hermes 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Hermes 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示向下箭头且新消息不强制打断阅读，点击箭头后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧以主题浅底气泡显示，AI 回复应在左侧保留 Agent 图标并使用开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
